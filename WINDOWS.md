# Подключение виртуального FC к Betaflight Configurator в Windows 11

Инструкция для двух путей: **A — по TCP (проще всего, 5 минут)** и **B — через настоящий COM-порт (com0com)**.
Путь A работает в настольном Configurator, путь B — ещё и в браузерной версии.

---

> **История изменений переехала** в [`CHANGELOG.md`](CHANGELOG.md): здесь остаётся только то,
> что нужно для подключения и диагностики в Windows.

## Путь A. TCP — настольный Configurator (рекомендуется)

### Шаг 1. Установить Python

1. Откройте <https://www.python.org/downloads/> → **Download Python 3.13.x** (Windows installer 64-bit).
2. В установщике **обязательно** поставьте галочку **Add python.exe to PATH**, затем *Install Now*.
3. Проверка: `Win+R` → `cmd` → Enter → наберите

   ```bat
   python --version
   ```

   Должно вывести `Python 3.13.x`. Если «не является внутренней командой» — откройте установщик
   снова, *Modify* → *Add to PATH*, либо используйте лаунчер `py` вместо `python`.

### Шаг 2. Положить проект на диск

1. Скопируйте папку `bfemu` (целиком, вместе с `bfemu\data`) в удобное место, например `C:\bfemu`.
2. Структура должна быть такой:

   ```
   C:\bfemu\
     ├─ bfemu\            (пакет: msp.py, fc.py, cli.py, server.py, data\)
     ├─ tools\  tests\
     ├─ run_windows.bat
     ├─ run_windows_com.bat
     ├─ README.md  WINDOWS.md
   ```

### Шаг 3. Запустить виртуальный FC

Двойной клик по **`run_windows.bat`** (или в консоли: `cd C:\bfemu` → `run_windows.bat`).

Ожидаемый вывод:

```
[FC] Betaflight 4.5.4 / MSP API 1.46.0 / настроек в базе: 683
[TCP] виртуальный FC слушает 127.0.0.1:5761 (в Configurator: manual connection, порт tcp://127.0.0.1:5761)
```

Окно **не закрывайте** — это и есть полётный контроллер. В нём же видно каждый MSP-запрос от Configurator.

При первом запуске Windows может спросить разрешение брандмауэра — для адреса `127.0.0.1` это не требуется,
но если окно появилось, нажмите *Allow*.

Дополнительно откроется **веб-монитор** состояния: <http://127.0.0.1:8088> — там видно активные фичи,
последние MSP-запросы и журнал CLI-команд (обновляется каждые 2 секунды).

### Шаг 4. Установить Betaflight Configurator (настольную версию!)

1. Откройте <https://github.com/betaflight/betaflight-configurator/releases/latest>.
2. Скачайте файл для Windows: **`Betaflight-2026.6.2-x64-setup.exe`** (13 МБ, сборка Tauri/desktop).
3. Установите, запустите.

> **Важно.** Браузерная PWA-версия Configurator **не умеет** сырой TCP — ей нужен путь B
> (Web Serial + com0com) или websockify. Настольная `.exe`-сборка умеет: в ней есть нативный
> транспорт TCP с портом по умолчанию 5761.

### Шаг 5. Подключиться

1. Справа вверху нажмите кнопку подключения (порт/устройство).
2. Выберите готовую закладку **«Betaflight SITL»** — она уже прописана как `tcp://127.0.0.1:5761`
   и совпадает с адресом нашего эмулятора.
   Если её нет: **Manual connection** (ручное подключение) → в поле адреса введите

   ```
   tcp://127.0.0.1:5761
   ```

   (формат допускает и `127.0.0.1:5761`, и просто `127.0.0.1` — порт 5761 подставится сам) → **Connect**.

3. В логе Configurator появится:

   ```
   Serial port opened: tcp://127.0.0.1:5761
   API version: 1.46.0
   FC info: BTFL 4.5.4
   Board info: VIRTUALFC 0
   ```

   А в окне эмулятора побегут строки вида `[MSP] 0x0001 MSP_API_VERSION (0 -> 3 байт)`.

### Шаг 6. Проверить, что всё живо

| Что открыть | Что должно быть |
|---|---|
| **Setup** | плата `STM32F405 (S405)`, прошивка `4.5.4`, сенсоры gyro/acc/baro, напряжение ~16.8 В |
| **Motors** | 4 мотора, ползунки реагируют (моторы, конечно, не крутятся) |
| **Ports** | таблица портов заполнена в порядке прошивки — USB VCP первой строкой, затем UART1…UART5; скорости заводские (115200 / 57600 / AUTO / 115200); жёлтой плашки про таблицу VTX нет |
| **Корректирование в полёте** | 30 слотов по 6 байт; включено 4 слота (RC Rate, RC Expo, профиль рейтов, сила Horizon) — вкладка показывает таблицу, а не пустую страницу |
| **OSD** | 80 элементов, 31 статистика, 2 таймера, 19 предупреждений, 3 профиля; раскладка заполнена (напряжение, предупреждения, таймер, газ, высота, спутники, имя, RSSI) |
| **Configuration / PID Tuning** | настройки читаются и сохраняются, значения — реальные для 4.5.4 |
| **CLI** | нажмите вкладку, дождитесь `Entering CLI Mode, type 'exit' to reboot, or 'help'` и приглашения `# ` |

Что попробовать в CLI:

```
status
version
get gyro_lpf1_static_hz
set gyro_lpf1_static_hz = 300
diff all
dump
save
```

* `get`/`set` вернут реальные диапазоны и заводские значения из прошивки 4.5.4;
* `save` и `exit` имитируют перезагрузку: линк рвётся, эмулятор «загружается» ~1.5 с,
  Configurator переподключается (в логе — `Power on reset` / повторное рукопожатие);
* значения, сохранённые через `save`, живут до перезапуска `run_windows.bat`.

### Остановить

`Ctrl+C` в окне эмулятора или просто закрыть окно.

## Путь B. Настоящий COM-порт через com0com (работает и в браузерной версии)

Идея: com0com создаёт пару связанных портов `COM10 <-> COM11`.
Configurator подключается к `COM10` как к обычному FC, а эмулятор занимает `COM11`.

### Шаг 1. Установить com0com

1. Скачайте **подписанную** сборку com0com (например, с <https://sourceforge.net/projects/com0com/>
   или сборку `com0com-3.0.0.0-i386-and-x64-signed` от сообщества) и установите.
2. Если при установке предложат отключить проверку подписи драйверов — лучше взять подписанную версию,
   чтобы не трогать настройки безопасности Windows.

### Шаг 2. Создать пару портов

Запустите **Setup Command Prompt** (из меню Пуск, ярлык com0com) и выполните:

```bat
install PortName=COM10 PortName=COM11
```

Проверить созданное: `list` (должны появиться `COM10` и `COM11`).
Порты видны в **Диспетчере устройств** → *Порты (COM и LPT)*.

### Шаг 3. Запустить эмулятор на COM11

```bat
cd C:\bfemu
run_windows_com.bat COM11
```

или напрямую:

```bat
python -m bfemu --com COM11 --http 8088
```

В окне появится `[COM] порт \\.\COM11 открыт ...`.

> Если стоит `pyserial` (`pip install pyserial`), эмулятор использует его; без него порт
> открывается как файл — для байтового моста этого достаточно.

### Шаг 4. Подключиться к COM10

1. Настольная версия: в списке портов выберите `COM10` → **Connect**.
2. Браузерная PWA: **Connect** → *Serial* → в системном диалоге выберите `COM10` → *Подключить*.
   Web Serial видит виртуальную пару так же, как реальный USB-UART.

Дальше всё то же: Setup/CLI/`dump`/`save`.

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| `python: command not found` | Python не в PATH → используйте `py -m bfemu ...` или переустановите с галочкой *Add to PATH* |
| Configurator пишет «Failed to open serial port» | порт занят другим приложением (закройте прошлый экземпляр эмулятора, Arduino IDE, Betaflight CLI-терминалы) |
| В браузерной версии нет поля для `tcp://` | это PWA — у неё нет сырых сокетов; используйте путь B или настольную `.exe`-сборку |
| В Configurator подключилось, но вкладки пустые | проверьте окно эмулятора: если идут ошибки, пришлите строки `[MSP] 0x....` — это коды нереализованных сообщений |
| Хочу посмотреть, что происходит | веб-монитор <http://127.0.0.1:8088> и `tests\smoke_test.py` (610 проверок протокола, CLI и вкладок) |
| Нужен «чистый» FC с заводскими настройками | перезапустите эмулятор: состояние не пишется на диск, `save` живёт только до выхода |
| На «Приёмнике» рыск уезжает в AUX, коптер в «Предпросмотре» крутится, полосы «прыгают» | каналы пишут ДВА инструмента сразу: осталось открытым прежнее окно `run_tx_joystick.bat` / `python tools\tx.py joystick`. Новое окно теперь останавливается с подсказкой, а на `/tx` появляется предупреждение «Каналы пишут несколько источников». Нажмите Ctrl+C в лишнем окне и запустите инструмент заново (см. раздел 21) |
| В консоли инструмента: «Закрывайте чужое окно: `taskkill /PID 28888 /F`» / «ЧУЖОЕ окно» | инструмент сам нашёл второе окно по PID. Закройте его указанной командой (или просто нажмите Ctrl+C в том окне), либо запускайте `run_tx_joystick.bat` — он закрывает чужие окна сам (`--kill-others`) |
| В консоли инструмента: «каналы уже ведёт другой запуск инструмента (PID …)» или «каналы только что писал другой источник: …» | это второе, не закрытое окно инструмента. Нажмите в нём Ctrl+C (или закройте окно) и запустите одно окно заново. Сверьте дату сборки в шапке окна — старое окно печатает прежнюю дату (или не печатает её вовсе) |
| Тумблеры и крутилки не появляются в Configurator | их надо назначить на каналы в микшере пульта (`MODEL SETUP → MIXES`, обычно CH5…CH8) и откалибровать: `python tools\tx.py joystick --detect-aux`. Если ось не шевелится даже в `tools\tx.py axes` — дело в пульте, а не в эмуляторе |
| Тумблер лёг не на тот AUX-канал | инструмент печатает раскладку и назначение; номер канала меняется ключом `--aux-map 3=switch2:3` (ось 3 → AUX3). Посмотреть в Configurator, какая полоса двигается, тоже можно — режим назначается на тот канал, который реально ходит |
| Вкладка «Корректирование в полёте» пустая | либо в ответе на `MSP_ADJUSTMENT_RANGES` нет слотов (старая сборка), либо все 30 слотов выключены после `defaults` — так и должно быть. Обновите архив: в шапке монитора должно быть «сборка 2026-09-27-c» |
| Вкладка OSD пустая | в ответе `MSP_OSD_CONFIG` пришли нулевые флаги — так было в старых сборках. Обновите архив и перезапустите эмулятор: в шапке монитора должно быть «сборка 2026-09-27-b» |
| Порт 5761 занят | запустите на другом порту: `python -m bfemu --tcp 127.0.0.1:6761 --http 8088` и укажите `tcp://127.0.0.1:6761` |

## Почему SOFTSERIAL не видно во вкладке «Порты»

Так задумано и на железе: софт-серийные порты появляются в списке **только при включённой фиче**
(прошивка убирает их из доступных, пока `softserialEnabled == false`). Правильная последовательность:

1. Вкладка **Конфигурация** → галочка **SOFTSERIAL** → **Сохранить и перезагрузить**.
2. В окне эмулятора должны появиться строки:
   ```
   [MSP] фичи сохранены: AIRMODE, OSD, SOFTSERIAL
   [FC] фича SOFTSERIAL: добавлены порты SOFTSERIAL1/2
   [FC] конфигурация записана в «флеш»: C:\bfemu\eeprom.json
   ```
3. После переподключения открыть **Порты** — внизу таблицы будут строки `SOFTSERIAL1` и `SOFTSERIAL2`.

Если строк нет — сначала убедитесь, что окно эмулятора перезапущено после распаковки новой версии
(старый процесс продолжает работать со старым кодом), и посмотрите
<http://127.0.0.1:8088/api/state> — там в разделе `"ports"` сразу видно, что отдаёт FC:

```json
"ports": [ ... {"name": "VCP"}, {"name": "SOFTSERIAL1", "functions": []}, {"name": "SOFTSERIAL2", "functions": []} ]
```

## Если изменение всё же не сохранилось

Каждый обработчик MSP обёрнут в проверку: если внутри что-то падает, эмулятор пишет в лог

```
[X] ошибка в обработчике 0x0025 MSP_SET_FEATURE_CONFIG (4 байт):
Traceback ...
```

Вместо прежнего «молчаливого» отсутствия ответа. Если увидели такую строку — пришлите её текст,
это точное указание, что чинить.

Отдельно про **фичи и SOFTSERIAL**: включение галочки во вкладке «Конфигурация» пишется во «флеш»
(кнопкой **Сохранить и перезагрузить**) и переживает перезапуск. При включении SOFTSERIAL во вкладке
**Порты** появляются строки `SOFTSERIAL1`/`SOFTSERIAL2`, при выключении — исчезают, как на железе.

## Сохраняется ли конфигурация между запусками

Да, с этой версии — эмулятор держит «флеш» в файле **`C:\bfemu\eeprom.json`** (путь можно изменить
флагом `--eeprom`, отключить — `--eeprom none`).

Проверка на примере вкладки «Датчики»: выключите **Акселерометр** → нажмите
**Сохранить и перезагрузить** → в логе эмулятора появятся строки

```
[MSP] конфигурация датчиков: acc=1 baro=0 mag=1 sonar=0
[FC] конфигурация записана в «флеш»: ...\eeprom.json
```

→ Configurator переподключится, а галочка останется снятой. То же самое с настройками во вкладках
Конфигурация, Приёмник, Питание, FailSafe, PID, Фильтры, GPS Rescue и др.

Как это работает (как на настоящем FC):

* изменения в любой вкладке применяются к «RAM» и теряются, если закрыть Configurator без сохранения;
* кнопка **«Сохранить»** / **«Сохранить и перезагрузить»** (или `save` в CLI) — пишет конфигурацию в
  `eeprom.json`; эмулятор покажет `[FC] конфигурация записана в «флеш»: ...\eeprom.json`;
* при следующем запуске `run_windows.bat` в логе видно
  `[FC] конфигурация загружена из «флеша»` — значения, фичи, порты, AUX-режимы, имена и UID на месте;
* `defaults` (в CLI) сбрасывает к заводским настройкам **и** записывает их во «флеш»;
* `exit` без `save` — изменения теряются (как в прошивке).

Полный сброс к заводскому состоянию — любой из способов:

```bat
del C:\bfemu\eeprom.json
python -m bfemu --wipe                 :: стереть «флеш» перед запуском
python -m bfemu --eeprom none          :: вообще не сохранять между запусками
```

Либо нажмите **«Сбросить настройки»** в Setup — Configurator отправит `MSP_RESET_CONF`, и эмулятор
сбросит конфигурацию с записью во «флеш», как это делает `resetEEPROM()` в прошивке.

## Закладка «Betaflight SITL» не появилась — это нормально

**«Betaflight SITL»** — обычное сохранённое подключение, которое приложение создаёт
**один раз, при самом первом запуске**, когда хранилище настроек ещё пустое
(`stores/connectionBookmarks.js`: сид срабатывает при условии «ключ ещё никогда не записывался»).
Если Configurator был установлен раньше — ключ уже есть, и сид не выполняется. Кроме того, закладка
попадает в меню только если сборка умеет открывать такой адрес (`serial.canOpen`) — то есть в
настольной версии (Tauri) и на Android, но не в браузерной PWA.

Ручное подключение делает то же самое, поэтому закладка — просто удобство. Свою завести так:

1. **Подключиться** → **Выбрать вручную**.
2. В поле **«Порт:»** введите `tcp://127.0.0.1:5761` (подсказка: «Введите последовательный порт или URL для подключения»).
3. В поле **«Имя:»** напишите, например, `bfemu - виртуальный FC`.
4. Нажмите кнопку с иконкой закладки — **«Сохранить»** (если адрес уже сохранён, она называется «Обновить»).
5. Нажмите **«Подключиться»**.

Адрес появится в разделе **«Сохранённые подключения»** и в меню кнопки «Подключиться» —
открывается в один клик. Удаляется кнопкой с иконкой корзины («Удалить сохранённое подключение»).

> Можно держать несколько закладок: `tcp://127.0.0.1:5761` для эмулятора на порту по умолчанию
> и, например, `tcp://127.0.0.1:6761` для запуска через `run_windows.bat 6761`.

## Окно `run_windows.bat` закрывается сразу после запуска

Это почти всегда не эмулятор, а сам `.bat`: `cmd.exe` капризен к переносам строк и не любит
кириллицу в кодировке консоли. В текущей версии лончер написан **только ASCII + CRLF**,
пишет лог в `logs\bfemu.log` и **всегда** заканчивается `pause`.

Порядок действий:

1. **Скачайте проект заново** (`bfemu-windows.zip`), распакуйте в `C:\bfemu` и, если Windows
   пометил файлы как скачанные — щёлкните правой кнопкой по архиву **до распаковки** →
   *Свойства* → галка **Разблокировать** → ОК. Иначе SmartScreen может блокировать `.bat`.
2. Запустите **`run_windows_debug.bat`** — он печатает, где лежат файлы, какой Python найден,
   и оставляет окно открытым с `cmd /k`. Это самый быстрый способ увидеть причину.
3. **Самый надёжный способ — запуск из уже открытой консоли** (окно физически не может закрыться):

   ```bat
   cd C:\bfemu
   python -u -m bfemu --tcp 127.0.0.1:5761 --http 8088 --log logs\bfemu.log
   ```

   Если и здесь ничего не выводится — проблема в Python, см. таблицу ниже.
4. Альтернатива `.bat`: **`run_windows.ps1`** (PowerShell). Запуск:
   правый клик → *Выполнить с помощью PowerShell*, либо в консоли
   `powershell -ExecutionPolicy Bypass -File .\run_windows.ps1`.
5. Если консоль вообще ничего не показала — посмотрите **`logs\bfemu.log`**: эмулятор пишет
   туда всё, что печатает на экран, ещё до любых ошибок Python.

Что означают типичные коды выхода:

| Код | Что случилось | Что делать |
|---|---|---|
| `3` | Порт MSP занят (5761) | Запустите `run_windows.bat 6761` и подключайтесь к `tcp://127.0.0.1:6761`, либо закройте прошлый экземпляр эмулятора. Веб-порт ведёт себя мягче: если 8088 занят, монитор поднимется на 8089 и напишет об этом в логе — эмулятор не упадёт |
| `1` | Ошибка внутри Python | Открыть `logs\bfemu.log` — там полный traceback |
| `9009` / мгновенный выход | `python` — это заглушка Microsoft Store | Установите Python с <https://www.python.org/downloads/> (галка *Add to PATH*) или используйте лаунчер `py` |

Отдельно проверьте, что **не мешает антивирус**: некоторые сборки Defender/SmartScreen блокируют
неподписанные `.bat` из интернета. Признак — окно исчезает за доли секунды без единой строки текста.
В этом случае файл нужно разблокировать (шаг 1) или запускать через `run_windows_debug.bat` / PowerShell.

Ещё одна частая причина «пустого» окна: в PATH есть только `py`, а не `python`. Лончер это умеет:
он проверяет оба варианта и сам выбирает подходящий, выводя строку `[i] Python 3.13.x`.

cd C:\bfemu
python tests\smoke_test.py       :: 481 проверка MSP, CLI, вкладок и ребута
python tools\check_softserial.py :: вкладка «Порты»: SOFTSERIAL1/2 (30/31)

python tools\check_osd_tab.py    :: вкладка «OSD»: элементы, статистика, таймеры, предупреждения

запросы, которые делает Configurator при подключении.
