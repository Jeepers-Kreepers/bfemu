# Стиль текста курса «Тренажёрная подготовка внешнего пилота БВС»

Обязательные требования к языку всех статей курса. Документ составлен на основе
правки первого пакета (вводный модуль + статья 1.1.05) и применяется ко всем
остальным 46 статьям без исключения.

Главный принцип: **текст пишется полным нормативным техническим русским языком.
Сокращения фраз, разговорные обороты и профессиональный жаргон не допускаются.**

## 1. Запрещённые приёмы

### 1.1. Сокращение и усечение фраз

Фраза пишется полностью, в законченной грамматической форме.

| Нельзя | Нужно |
|---|---|
| Тренажёрная подготовка — не «поиграть в симулятор» | Тренажёрная подготовка — это не игра в симулятор |
| Почему стек, а не один симулятор | Почему используется комплект программных средств, а не один симулятор |
| Как понять, что симулятор «похож» | Как определить соответствие модели симулятора реальному аппарату |
| Перенос навыка: тренажёр → реальный полёт | Перенос навыка: тренажёр и реальный полёт |
| норматив 20 ч | норматив 20 часов |
| Упр. 3.2ТП | Упражнение 3.2ТП |
| Drill 1 | Элемент 1 |
| доп. камера/подвес | дополнительная камера или подвес |
| 8+ каналов | 8 и более каналов |

### 1.2. Стрелка «→» как замена сказуемому

Стрелка допустима **только** для буквальных путей в интерфейсе программы:
`Mission Planner → Simulation`, `USB mode → Joystick`, `Settings → Video`.

Во всех остальных случаях перечисление раскрывается словами:

| Нельзя | Нужно |
|---|---|
| распознать → доложить → перейти в резервный режим → завершить | распознать, доложить, перейти в резервный режим и завершить |
| самооценка → запись → лог → классификация ошибки | самооценка, запись в книжку, анализ журналов, классификация ошибки |
| rates и hover throttle → масса и инерция → камера → среда | сначала rates и hover throttle, затем масса и момент инерции, далее параметры камеры и параметры среды |
| разминка → основная часть → зачётный проход → разбор | разминка, основная часть, зачётный проход, разбор |

### 1.3. Знак «+» как замена союза

Знак «плюс» допустим **только** в арифметических выражениях и расчётах:
`показ 5 минут + разбор 10 минут = 15 минут`, `1000 / частота_Гц мс + отклик панели`.

В перечислениях раскрыть словами:

| Нельзя | Нужно |
|---|---|
| Liftoff + Uncrashed + ArduPilot SITL | Liftoff, Uncrashed и ArduPilot SITL |
| запись экрана + журнал занятия + логи SITL | запись экрана, журнал занятия и журналы полёта SITL |
| амортизация ПК + лицензия + электричество | амортизация компьютера, лицензия и электроэнергия |
| левый стик: газ + рысканье | левый стик: газ и рысканье |
| тренажёрное устройство + программа планирования | тренажёрное устройство и программа планирования |
| <td>+ второй пульт</td> | <td>дополнительно второй пульт</td> |

### 1.4. Косая черта «/» как замена союза

В связном тексте косая черта не используется. Раскрывается в «и», «или», «либо».

### 1.7. Кавычки как способ снять ответственность за разговорное слово

Кавычки «ёлочки» используются только для:
- точных названий документов, режимов, пунктов интерфейса, литералов параметров;
- прямой речи и радиообмена («Передаю управление» — «Принял управление»);
- цитат из нормативных актов.

Кавычки **не** используются для того, чтобы снять с себя ответственность за
разговорное слово. Если слово требует кавычек как «ненастоящее» — его надо
заменить нормативным:

| Нельзя | Нужно |
|---|---|
| «поиграть в симулятор» | игра в симулятор |
| «налетал 4 часа» | «выполнено четыре часа налёта» |
| «другой аппарат» | управление другим аппаратом |
| «из даташита рамы» | из технических данных рамы |
| «по памяти» | по памяти (без кавычек) |
| «в основном положительные» | преимущественно положительные |

## 4. Требования к построению фразы

1. **Полное предложение.** Каждая мысль излагается законченным предложением
   с подлежащим и сказуемым. Назывные конструкции допустимы только в ячейках
   таблиц и в пунктах чек-листа.
2. **Один тезис — одно предложение.** Сложноподчинённые конструкции длиной
   более трёх строк разбиваются.
3. **Безличность.** «Рекомендуется зафиксировать…», «Необходимо проверить…».
   Первое лицо единственного числа не используется. Первое лицо множественного
   числа («фиксируем», «ведём») допустимо в методических указаниях.
4. **Активный залог предпочтителен.** «Инструктор фиксирует версию» вместо
   «Версия фиксируется инструктором».
5. **Без вводных слов-паразитов.** «вообще», «на самом деле», «кстати»,
   «в целом», «просто», «типа», «как бы» не используются.
6. **Без оценочных превосходных степеней без основания.** «лучший», «самый
   удобный» — только с указанием критерия и источника.
7. **Числа с обоснованием.** Любое число в тексте имеет источник или помечено
   как учебный ориентир.

## 4bis. Запрет знаков «<» и «>» в тексте материала

**Это требование связано с ошибкой импорта MySQL 1366, а не только со стилем.**

Знак «<» в тексте материала (как правило, внутри формул MathJax) приводит
к ошибке при импорте в Joomla Zoo:

```
1366 Incorrect string value: '\xBD\xD0\xB0 16...' for column
`s963429_backup10p0qp_zoo_search_index`.`value` at row 2
```

Истинный механизм (подтверждён исходным кодом Zoo и Joomla framework,
воспроизведён в PHP — см. `validate_zoo_search.php`):

1. При сохранении материала Zoo строит поисковый индекс
   (`packages/com_zoo/admin/tables/item.php`): значение каждого элемента
   пропускается через `JFilterInput::getInstance()->clean($value)` и вставляется
   в таблицу `{prefix}zoo_search_index`, колонка `value` (TEXT, FULLTEXT, CHARSET=utf8).
2. Фильтр Joomla для типа `string` выполняет
   `cleanString() = remove(decode($source))`, где
   `decode() = html_entity_decode($source, ENT_QUOTES, 'UTF-8')`.
   **Сущность `&lt;` декодируется обратно в голый знак «<» — экранирование
   сущностями не помогает, ошибка сохраняется.**
3. Далее `cleanTags()` разбирает текст как HTML побайтовыми `strpos`/`substr`,
   принимая этот «<» за начало «неправильного тега». Из-за смещений,
   рассчитанных от другой строки, разрез попадает в середину двухбайтового
   кириллического символа: ведущий байт теряется, остаётся осиротевший
   байт-продолжение (`\xBD`). MySQL в строгом режиме отклоняет такую строку.

**Правило: в тексте материала знаков «<» и «>» не должно быть ни в каком виде —
ни голых, ни сущностями `&lt;`, `&gt;`, `&#60;`, `&#62;`.**

| Нельзя | Нужно |
|---|---|
| `\( 3{,}90 < 4{,}0 \)` | `\( 3{,}90 \lt 4{,}0 \)` |
| `\( 3{,}90 &lt; 4{,}0 \)` | `\( 3{,}90 \lt 4{,}0 \)` |
| `\( 8\ \text{м} > 5\ \text{м} \)` | `\( 8\ \text{м} \gt 5\ \text{м} \)` |
| `= -16{,}5° < 0` | `= -16{,}5° \lt 0` |
| «(УВ &lt; 90°)» в обычном тексте | «(УВ меньше 90°)» |
| «(УВ &gt; 90°)» в обычном тексте | «(УВ больше 90°)» |

Макросы `\lt` и `\gt` — штатные макросы MathJax: рендерятся идентично знакам
«<» и «>», но в сыром тексте содержат только ASCII-буквы, поэтому фильтр Joomla
их не затрагивает. В обычном тексте (вне формул) сравнения записываются словами
«меньше» и «больше».

Автоматика:
- `fix_angles.py` — автоматически заменяет угловые знаки внутри формул
  `\( … \)` / `\[ … \]` на `\lt` / `\gt`; вхождения вне формул считает
  нарушением (переписываются словами вручную). Проверка: `python3 fix_angles.py --check`
  (код возврата 1 при любом нарушении);
- `build_csv.py` — применяет `normalize_angles()` при каждой сборке и останавливает
  сборку, если в тексте вне формул остался угловой знак;
- `check_style.py` — пункт 0: любой знак «<»/«>» вне тегов (голый или сущностью)
  считается ошибкой;
- `validate_zoo_search.php` — финальная валидация: прогоняет `Text1` и `Teaser`
  каждой строки CSV через настоящий `Joomla\Filter\InputFilter` (копия исходника —
  в `vendor-joomla/`) и проверяет результат на корректность UTF-8 и отсутствие
  4-байтовых символов (колонка `value` — utf8mb3).

Эталонный файл `zoo_import_vse-108-fixed(4).csv` содержит 4 голых знака «<»
(например `250 < 300: «OK»`) — валидатор подтверждает: в этих местах фильтр
обрабатывает «<» без повреждения UTF-8, эталонный файл импортируется безопасно.
Однако гарантия отсутствует: результат зависит от положения знака относительно
соседних тегов. В наших файлах угловых знаков в тексте нет вовсе.

## 5. Оформление

- Кавычки — только «ёлочки». Внутри «ёлочек» при необходимости — „лапки“.
- Тире — длинное (—), с пробелами с обеих сторон. Дефис — только внутри слов.
- Неразрывный пробел (`&nbsp;`) ставится между числом и единицей измерения,
  между предлогом и числом в таблицах.
- Диапазоны — через короткое тире без пробелов: `20–30 мс`, `5–10 м/с`.
- Процент: `40 %` (с неразрывным пробелом).
- Формулы — только MathJax в `\( … \)`, в таблицах допускается `\text{…}`.
- Латиница в тексте — только для названий продуктов, параметров, режимов
  и цитат из интерфейса. Смешанные написания (`пропwash`, `реда模型`) запрещены.

## 6. Самопроверка статьи перед сдачей

Перед включением статьи в CSV выполнить проверки (скрипт `check_style.py`):

0. Нет знаков «<» и «>» в тексте ни в каком виде — ни голых, ни сущностями
   `&lt;`/`&gt;`: в формулах MathJax применяются макросы `\lt`/`\gt`, в тексте — слова
   «меньше»/«больше» (`python3 fix_angles.py --check`).
1. Нет иероглифов CJK и смешанных русско-латинских склеек.
2. Нет стрелок «→» вне буквальных путей интерфейса.
3. Нет косых черт «/» и знаков «+» в перечислениях связного текста.
4. Нет слов из стоп-списка (раздел 1.4, 1.5).
5. Нет сокращений «астр. ч», «Упр.», «Drill», «N ч», «N мин» в связном тексте.
6. Все якоря `href="#…"` имеют соответствующие `id="…"`.
7. Все парные теги сбалансированы.
8. Оглавление (uk-accordion) дословно совпадает с заголовками `<h2>`/`<h3>`.
9. Teaser Description — один `<p>`, 250–400 знаков, без аббревиатур без раскрытия.
10. Присутствуют все обязательные элементы разметки: `note-inline`,
    `danger-inline`, `ok-inline`, `uk-card` (практика), чек-лист с
    `type="checkbox"`, нумерованные источники, строка «Проверено: ДД.ММ.ГГГГ»,
    кнопки «↑ К оглавлению».
