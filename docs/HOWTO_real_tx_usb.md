# Подключение реальной аппаратуры (Zorro и др.) по USB — шаг за шагом

Что получится: двигаете стики настоящего пульта — на вкладке **«Приёмник»** едут полосы каналов,
модель в **«Предпросмотре»** наклоняется, тумблеры (AUX) включают режимы на вкладке «Режимы».
Выглядит так, будто пульт связан с приёмником виртуального FC.

Есть два пути. **Путь А (проще, по USB-кабелю)** — пульт подключается к компьютеру как
USB-джойстик, приёмник и бинд не нужны. **Путь Б** — настоящий приёмник в USB-UART переходнике
(настоящий эфир и настоящий бинд), см. в конце.

---

## Сначала проверьте, что запущена свежая сборка

Запущенный эмулятор держит в памяти ту страницу, которая была на момент старта, поэтому после
распаковки архива эмулятор **нужно перезапустить**. Признаки свежей сборки:

* в окне эмулятора при запуске печатается строка
  `[FC] сборка 2026-09-25, страница аппаратуры v3 (кнопки «Связать (Bind)» / «Развязать» — на /tx)`;
* в шапке страницы <http://127.0.0.1:8088/tx> — `сборка 2026-09-25 (страница аппаратуры v3)`
  и видны **три** карточки сверху вниз: «Подключение аппаратуры (USB)», «Бинд (связывание с
  аппаратурой)», «Стики»;
* `python tools\tx.py selftest` печатает «ВСЕ САМОПРОВЕРКИ ПРОЙДЕНЫ» (в старых сборках такой
  команды просто нет).

В браузере после этого нажмите **Ctrl+F5** (обновить, минуя кэш).

---

## Как это выглядит на странице /tx

1. **«Подключить аппаратуру»** — управление переходит к настоящей аппаратуре: ползунки, тумблеры и
   крутилки на странице гаснут (виртуальная аппаратура «отключается»).
2. Запускаете `run_tx_joystick.bat` (пульт по USB) или `run_tx_wire.bat` (приёмник в COM-порту).
3. **«Связать (Bind)»** — создаёт связь с виртуальным контроллером: после этого каналы
   активируются и на вкладке «Приёмник» поедут полосы. До бинда там «Этап 1» и предупреждение о
   потерянной связи — так и должно быть.
4. **«Отключить (выдернуть USB)»** — настоящая аппаратура отсоединена, управление возвращается
   странице: ползунки снова активны (и снова нужен «Связать», чтобы каналы заработали).

При Ctrl+C в консольных режимах управление автоматически возвращается странице.

## Путь А: пульт как USB-джойстик

### Библиотеки не нужны

Пульт читается **встроенным способом Windows** (системный интерфейс winmm) — тот же, что
используют «Игровые устройства»: `Win+R` → `joy.cpl`. Никаких `pip install` для режима `joystick`
делать не надо, и сборка пакетов из исходников (когда pip «висит» на
`Getting requirements to build wheel`) не запускается.

Ограничение этого интерфейса: до 6 осей и 32 кнопок на устройство — у пульта их меньше, так что
хватает с запасом; «шляпа» (POV) тоже читается и уходит в AUX. Для режима `wire`/`crsf` (приёмник
в COM-порту) нужен только `pyserial`.

### Шаг 1. Что нужно

* Windows (встроенное чтение пульта работает только там) и аппаратура (Zorro, TX16S, Boxer, …)
  с прошивкой EdgeTX или OpenTX;
* USB-кабель **для данных**, а не «только зарядка» (у Zorro — порт USB-C сверху);
* запущенный эмулятор: `C:\bfemu\run_windows.bat` (окно не закрывать);
* Configurator, открытая вкладка **«Приёмник»**.

Проще всего запустить `C:\bfemu\run_tx_joystick.bat`: он печатает версию Python, показывает оси
и сразу начинает вести каналы. Ничего доустанавливать не нужно.

Вручную (если хотите через консоль):

```bat
cd C:\bfemu
python tools\tx.py axes            :: оси и значения
python tools\tx.py joystick        :: вести каналы
```

### Шаг 2. Включить на пульте режим USB Joystick

На Zorro (EdgeTX) включите пульт и:

1. Нажмите **MDL** (долгое нажатие) — попадёте в **MODEL SETUP**.
2. Пролистайте список до пункта **USB Joystick**.
3. Нажмите **Enter**: пульт переключится в режим джойстика (на экране — «USB Joystick
   connected» или индикация режима).

Альтернатива для любой модели: подключить USB-кабель и в появившемся меню режимов USB выбрать
**USB Joystick** (в EdgeTX: USB Storage / USB Serial / **USB Joystick**).

> Если выбрать «USB Storage» или «USB Serial» — джойстика в системе не будет, и скрипт скажет
> «USB-пульт не найден».

### Шаг 3. Проверить, что Windows видит пульт

1. Нажмите **Win+R**, введите `joy.cpl`, Enter.
2. В списке должен появиться пульт (например, «EdgeTX Joystick» / «Zorro»).
   Кнопка **«Свойства»** → подвигайте стики: ползунки должны ходить.
   Если центры «плывут» — тут же есть «Параметры → Калибровать».

### Шаг 4. Посмотреть оси

```bat
cd C:\bfemu
python tools\tx.py axes
```

Скрипт на 5 секунд покажет все оси и текущие значения — подвигайте стики и убедитесь, что
меняются те оси, что ожидаете. Для EdgeTX (порядок каналов AETR) типичная картина:

| Ось | Канал пульта | Полоса в Configurator |
|---|---|---|
| 0 | CH1 Aileron | Крен |
| 1 | CH2 Elevator | Тангаж |
| 2 | CH3 Throttle | Газ |
| 3 | CH4 Rudder | Рыск |
| 4…7 | CH5…CH8 (тумблеры) | AUX 1…4 |

Тумблеры попадают в оси 4…7 только если в микшере пульта они назначены на каналы 5…8
(MODEL → MIXES). Свободные оси и кнопки скрипт сам раздаёт в AUX 1…12.

### Шаг 4б. Если стики двигают не свои каналы — калибровка

Симптом: двигаете рыск — едет AUX2, а коптер в «Предпросмотре» вращается сам (крен, тангаж и
рыск попали на чужие оси). Это раскладка осей — на разных моделях пультов она своя.

```bat
python tools\tx.py joystick --detect
```

Отпустите стики и нажмите Enter — дальше четыре шага: крен вправо → тангаж вверх → рыск вправо →
газ. Газ идёт последним и «прокачивается» вверх-вниз (ручку оставить вверху): у него трещотка, и
ось ищется по размаху движения, а не по положению в покое. После подсказки просто отклоните стик до упора: инструмент **сам** увидит движение,
определит ось и направление и перейдёт к следующему шагу (Enter между шагами не нужен). Раскладка
сохраняется в `tx_map.json` и подхватывается дальше автоматически. Если какой-то стик не
определился, раскладка **не сохраняется** — инструмент скажет об этом и попросит повторить, так
что каналы не поедут вразнобой.

Проверить, что получилось, можно и в консоли (инструмент печатает это при каждом запуске), и на
странице /tx:

```
оси пульта в покое (по ним видно, та ли раскладка):
   ось 0 (X) → Крен: +0.00 (центр)
   ось 1 (Y) → Тангаж: +0.00 (центр)
   ось 2 (Z) → Газ: +0.02 (середина)
   ось 5 (V) → Рыск: +0.00 (центр)
каналы: Крен — ось 0 (X), сейчас +0.00; Тангаж — ось 1 (Y), сейчас +0.00; Газ — ось 2 (Z), сейчас +0.02; Рыск — ось 5 (V), сейчас +0.00
```

Главное правило: **крен, тангаж и рыск в покое должны быть в центре**. Если у одного из них
написано «упор внизу/влево» или «упор вверху/вправо» — каналу отдана чужая ось, и инструмент
скажет об этом сам и покажет плашку на странице /tx. Про газ придирок нет: у трещотки ручка
останавливается где угодно, в том числе в середине.

### Шаг 4в. Тумблеры и крутилки (AUX-каналы)

Стики настроены шагом 4б, а тумблеры и крутилки калибруются отдельно:

```
python tools\tx.py joystick --detect-aux
```

* переведите тумблер во все положения (трёхпозиционный — через все три);
* крутилку крутите до упоров в обе стороны;
* когда переключать больше нечего — подождите 8 секунд, калибровка закончится сама.

Инструмент сам определит, что это (тумблер на 2 или на 3 положения либо крутилка) и назначит
AUX-каналы: первый найденный тумблер → AUX1, второй → AUX2 и так далее. Раскладка сохранится
в `tx_map.json` и будет подхватываться при каждом запуске; её видно и на странице `/tx`
(в «Состоянии», строка `AUX-каналы`).

**Если тумблеры не определяются вообще** — они не назначены на каналы в микшере пульта. В режиме
USB Joystick EdgeTX/OpenTX отдаёт по USB только те каналы, что есть в модели:

1. На пульте: `MODEL SETUP → MIXES` → повесить тумблер на канал (`CH5`, `CH6`, …).
2. Проверить: `python tools\tx.py axes` — пощёлкать тумблером; должна шевелиться какая-то ось.
3. Перекалибровать: `python tools\tx.py joystick --detect-aux`.

### Шаг 5. Запустить

```bat
python tools\tx.py joystick
```

или то же самое двойным щелчком по **`run_tx_joystick.bat`**. Если оси «не те»:

```bat
python tools\tx.py joystick --map roll=0,pitch=1,throttle=2,yaw=3 --invert pitch
```

* `--map` — какой канал в какую ось (см. вывод `axes`);
* `--invert` — зеркалить каналы (типично для газа: если газ вверху — `--invert throttle`);
* `--index 1` — если устройств несколько (список печатается при запуске).

Выход — **Ctrl+C**: стики вернутся в центр, аппаратура «выключится», на вкладке «Приёмник»
появится предупреждение о потерянной связи — как будто пульт отключили.

### Шаг 6. Проверить результат

* **«Приёмник»**: полосы «Крен / Тангаж / Рыск / Газ» двигаются за стиками; AUX — за тумблерами.
* **«Предпросмотр»**: модель наклоняется и поворачивается; в покое стоит ровно.
* **«Режимы»**: назначьте AUX-канал на ARM/BEEPER/ANGLE и переключите тумблер.

Важно: каналы живут только если во вкладке **«Порты»** на каком-нибудь UART включена функция
**Serial RX** (по умолчанию — UART2). Если её выключить, полосы станут пустыми — так и должно быть.

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| Скрипт пишет «каналы уже ведёт другой запуск инструмента (PID …)» | это защита от двух окон: нажмите Ctrl+C в прежнем окне (или закройте его) и запустите снова. Если прежний запуск точно закрыт — подождите пару секунд или добавьте `--force` |
| Скрипт пишет «не получилось открыть USB-пульт» | смотрите причину в тексте: пульт не в режиме USB Joystick, кабель «только зарядка», или эмулятор запущен не в Windows |
| «USB-пульт не найден» | пульт не в режиме USB Joystick, кабель «только зарядка», или пульт в режиме USB Storage/Serial |
| Пульт есть в `joy.cpl`, но не виден в скрипте | закройте другие программы, которые захватили джойстик (симуляторы FPV и т.п.), перезапустите скрипт |
| Два устройства в списке | запустите с `--index 1` (или `--index 0`) |
| Газ/рыск работают наоборот | `--invert throttle` / `--invert yaw` или заново `--detect` |
| Тумблер не появляется ни на одном AUX | он не назначен на канал в микшере пульта (`MODEL SETUP → MIXES`, обычно CH5…CH8) — по USB пульт отдаёт только назначенные каналы. Проверьте `python tools\tx.py axes`, затем `python tools\tx.py joystick --detect-aux` |
| Тумблер лёг не на тот AUX-канал | смените номер вручную: `--aux-map 3=switch2:3` (ось 3 → AUX3); либо назначайте режим на тот канал, который реально двигается |
| Рыск двигает AUX, коптер вращается, полосы «прыгают» | **сначала** проверьте, не осталось ли открытым прежнее окно инструмента: два окна пишут каналы по очереди, и картинка «скачет». Новое окно теперь останавливается с подсказкой, а на `/tx` появляется «Каналы пишут несколько источников». Нажмите Ctrl+C в лишнем окне и запустите заново. Если окно одно — тогда раскладка осей не та: `python tools\tx.py joystick --detect` |
| После «Отключить (выдернуть USB)» ползунки «дёргаются» | раньше это была гонка двух источников; теперь данные пульта отклоняются (HTTP 409). Обновите архив |
| Ползунки на /tx «мертвы», в ответ на движение приходит 409 | каналами владеет аппаратура: нажмите на странице «Отключить (выдернуть USB)» |
| Инструмент видит не тот джойстик (несколько устройств) | `python tools\tx.py axes` покажет номера: запускайте `joystick --index N` |
| После калибровки всё равно не то | сверьте вывод: у стиков (крен, тангаж, рыск) в покое центр; про газ придирок нет — он может стоять и внизу, и в центре (трещотка); если нет — `--detect` заново, при необходимости пропишите вручную: `--map roll=0,pitch=1,throttle=3,yaw=2 --invert yaw` |
| Стики дрожат, центр не 1500 | калибровка в `joy.cpl` → «Свойства» → «Параметры» |
| Полосы в Configurator пустые | во вкладке «Порты» нет UART с Serial RX |
| «не вижу эмулятор на http://127.0.0.1:8088» | не запущен `run_windows.bat`; если порт другой — `python tools\tx.py --http 8089 joystick` |
| Тумблеры не влияют | назначьте каналы 5…8 на тумблеры в микшере пульта |

## Путь Б: настоящий приёмник в USB-UART переходнике (настоящий эфир и бинд)

Если аппаратура штатно биндится со своим приёмником, а приёмник можно подключить к компьютеру:

1. Приёмник → USB-UART переходник (для SBUS нужен инвертирующий; для CRSF — обычный),
   сигнальный провод приёмника к RX переходника, питание 5 В.
2. Запустите **`run_tx_wire.bat`** — он поставит `pyserial`, покажет список COM-портов и спросит
   порт. Вручную:

   ```bat
   python -m pip install pyserial
   python tools\tx.py ports                       :: какие порты есть
   python tools\tx.py wire --port COM5            :: автоопределение CRSF (420000) / SBUS (100000)
   python tools\tx.py wire --port COM5 --protocol sbus --baud 100000
   ```

3. Включите аппаратуру. Как только пойдут кадры, эмулятор считает, что **бинд состоялся**, и
   каналы поедут. Выключите пульт — «Этап 1» и предупреждение о потерянной связи, включите —
   полосы сразу оживут.

Проверка без железа: `python tools\tx.py selftest` (кодеки CRSF и SBUS + разбор потока из порта).

## Короткая шпаргалка

```bat
C:\bfemu\run_windows.bat            :: 1. эмулятор (окно не закрывать)
C:\bfemu\run_tx_joystick.bat        :: 2. пульт в режиме USB Joystick -> вести каналы
                                    ::    (ручной вариант: python tools\tx.py axes / joystick)
python tools\tx.py joystick --detect-aux   :: тумблеры и крутилки (AUX-каналы)
C:\bfemu\run_tx_wire.bat            ::    вместо пульта по USB: настоящий приёмник в COM-порту
```

Бинд: страница <http://127.0.0.1:8088/tx> → «Связать (Bind)» / «Развязать»
(или `python tools\tx.py bind` / `unbind`).
